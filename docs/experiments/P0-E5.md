# P0-E5 实验报告：多屏 GDI 截屏 + DPI 几何

- **日期**：2026-10-29（本地 13:12–13:16，UTC+8；应用日志为 UTC）
- **分支**：`feat/core`（Task 5）
- **结论**：**PASS（程序化）**。在真实运行的双屏混合 DPI 会话中，GDI 虚拟屏幕截屏得到 **3840×1080** 物理像素 PNG（左屏 1920×1080@150% 位于 `x=-1920`，主屏 1920×1080@100% 位于 `x=0`），双屏均被采集；8 个采样点与独立 `GetPixel` 读数逐通道一致；跨屏裁剪、4 dp→物理像素换算、`%LOCALAPPDATA%\Hangline\Screenshots` 原子写盘均已验证。唯一未覆盖的是**解锁桌面后左屏的真实桌面内容**（本次会话锁屏，Windows 锁屏只在主屏绘制，副屏为黑色；`GetPixel` 证明黑色就是真实屏幕内容，不是采集失败），见 §7。

## 3. 运行方式与 agent 沙箱限制

1. **workspace 内 exe 不能写 `%LOCALAPPDATA%`**（与 E3/E4 相同）：`cargo test` 直接在 workspace 内运行时，`save_png` 在创建 `...\Hangline\Screenshots\*.png.tmp` 时得到 `os error 5（拒绝访问）`。因此 E5 截屏测试把**测试二进制复制到 `%TEMP%\hangline-e5` 后运行**；真实应用也使用复制到 `%TEMP%` 的 debug exe。该限制不影响结论：同一二进制、同一代码路径，复制后写盘成功。
2. **锁屏**：桌面处于锁屏态。GDI 仍能抓取真实屏幕（主屏锁屏壁纸、副屏黑），所以尺寸/接缝/颜色链路的证据成立；但副屏真实桌面内容需解锁后人工复验（§7）。
3. **应用内临时 harness**：在 `setup` 中按 `HANGLE_E5_CAPTURE=<report path>` 启动一个线程，调用 `capture::grab_virtual_screen()`、`save_png()`、双屏裁剪，并写 `%TEMP%\hangline-e5\app-report.json`。该文件与 `lib.rs` 中的两行接线在提交前删除；提交的代码只含生产实现与测试。

### 5.6 DPI 感知对照（为什么必须 PMv2）

同一台机器、同一组 API：

| 进程 | DPI 感知 | 左屏 rect | 左屏 DPI | 结论 |
| --- | --- | --- | --- | --- |
| 应用（Tauri/tao） | `2`（Per-Monitor V2） | 1920×1080 | 144（150%） | 物理像素正确 |
| PowerShell 对照进程 | `0`（unaware） | 1280×720 | 96（100%） | Windows 把 150% 屏的监视器 rect/DPI 虚拟化，几何会错 |

因此 `geometry::monitors()` 与 `capture::grab_virtual_screen()` 都要求进程 PMv2；Tauri 运行时会设置，测试二进制则在 E5 测试开头显式 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`。上述对照进程只用于证明 monitor 几何会被虚拟化，截屏链路本身以 PMv2 应用进程的结果为准。

## 7. 手动待验证（需用户/controller 在解锁桌面或后续任务验收）

1. **解锁桌面后的双屏真实内容**：本次左副屏为黑是 Windows 锁屏只在主屏绘制导致；需解锁后重跑 E5，确认左屏桌面内容/窗口也能正确采集。尺寸、接缝、DPI、颜色链路已由 `GetPixel` 与跨进程哈希证明，此项只缺“副屏有真实内容”的样本。
2. **受保护/DRM 窗口**：Netflix/部分播放器的受保护表面在 GDI 截屏中可能为黑，这是 OS 限制；本机无可用 DRM 内容，未实测。代码按契约返回图像、不把黑色当错误。
3. **交互式框选（Task 16）**：本任务验证了 `crop` 的全图坐标换算与跨屏裁剪；截图浮层的鼠标框选、实时预览、Esc 取消属于 Task 16。
4. **顶部/上方显示器（负 y）与顶部/侧边任务栏**：合成单测覆盖（3 屏布局、顶部任务栏），本机没有上方显示器/侧边任务栏的真实硬件。
5. **150% 屏上的面板放置与命中 padding**：`dp_to_px` 与 hittest 换算已单测；当前面板实际在主屏（100%）运行。Task 10 按工作区放置到 150% 屏后应做一次真实鼠标验证。
6. **Asset protocol 读取自建截图**：`$LOCALDATA/Hangline/**` scope 与保存路径一致；本任务未通过 `convertFileSrc` 在面板里实际加载刚保存的 PNG（Task 10/16 使用截图时验证）。
7. **同一秒内连续两次截图**：文件名精确到秒，按规格会原子覆盖；如 Task 16 需要 burst 截图，需另行决定命名策略。
