## 2. 运行方式与 agent 沙箱限制

### 2.1 `pnpm tauri dev` 在本 agent 沙箱内无法启动

```
Running DevCommand (`cargo run ...`)
Running `target\debug\hangline.exe`
thread 'main' panicked at src\lib.rs:52:10:
error while running Hangline: PluginInitialization("log", "拒绝访问。 (os error 5)")
```

临时探针（已删除，未提交）在 app 进程内直接复现：**位于 workspace 内的 exe** 无法在 `%LOCALAPPDATA%` 下创建/打开文件：

```
probe dir="%USERPROFILE%\AppData\Local\app.hangline.Hangline\logs" exists=true
probe create_dir_all ok
probe open err "...\probe-app.log" -> Os { code: 5, kind: PermissionDenied, message: "拒绝访问。" }
probe dir="%USERPROFILE%\AppData\Local\Hangline\logs" exists=false
probe create_dir_all err=Os { code: 5, kind: PermissionDenied, message: "拒绝访问。" }
```

把**同一个 exe** 复制到 workspace 外再运行，同样的探针全部成功：

| exe 位置 | `%LOCALAPPDATA%` 写入 | 结果 |
| --- | --- | --- |
| `…\hangline\src-tauri\target\debug\hangline.exe` | 拒绝 (os error 5) | 启动即崩溃 |
| `…\hangline\.runtime-test\hangline.exe`（workspace 内子目录） | 拒绝 (os error 5) | 启动即崩溃 |
| `%USERPROFILE%\Documents\hangline-test\hangline.exe` | 成功 | 正常运行 |
| `%LOCALAPPDATA%\hangline-test\hangline.exe` | 成功 | 正常运行 |
| `%TEMP%\hangline-e1e2\run\hangline.exe` | 成功 | 正常运行 |

这是 **agent 沙箱对「workspace 内可执行文件」的文件写入限制**（同一份二进制、同一用户，仅路径不同），不是 Hangline 的缺陷；正常桌面上的 `pnpm tauri dev` 预期正常（见「手动待验证」）。为不动产品代码，本实验不改 log 插件配置。

## 4. 运行时观察：窗口尺寸 1.5×（已修正）

首次启动时窗口实测为 **2160×315**（而非 brief 要求的 1440×210），但 `scale_factor()` 返回 1.0、WebView2 视口 CSS 宽度 2160，前端上报卡片 `x=1005`。

原因：tao 按「逻辑位置 (0,0) 落在哪个显示器」选择创建缩放系数；本机左侧副屏为 150% DPI 且其右边界正好是 x=0，判断条件 `position.x <= monitor.x + width` 为闭区间，使 **副屏（150%）抢先匹配**，窗口按 1.5× 创建，随后落在主屏（96 DPI）上。属 Tauri/tao 的多屏 DPI 边界问题。

处理：`panel::create` 在 `build()` 后按窗口实际 DPI 重新应用逻辑尺寸：

```rust
win.set_size(tauri::LogicalSize::new(WIDTH, HEIGHT))?;
```

修正后实测：窗口 `0,0,1440,210`、DPI 96、`scale_factor() = 1`、前端上报 `x=645`，E1/E2 行为不变。该修正同时保证在 150% 主屏上仍得到 1440×210 dp。

## 5. 手动待验证（agent 无法确认，需 controller/用户）

1. **主观无感延迟/闪烁**：实测切换 25–41 ms，但「肉眼是否可感」「是否有闪一下」需要人眼判断（截图无法证明）。
2. **真实点击穿透到桌面**：本实验用 `WindowFromPoint` 验证了 OS 的点击路由，但**没有向用户桌面发送真实点击**（避免误触远端桌面上的应用）。建议人工点击透明区域，确认桌面/下层应用正常响应。
3. **`pnpm tauri dev` 正常启动**：本 agent 沙箱禁止 workspace 内 exe 写 `%LOCALAPPDATA%`，导致 log 插件初始化失败；需在普通桌面重跑 `pnpm tauri dev` 确认（预期正常，但未实测）。
4. **生产构建**：NSIS 打包后的透明/置顶/点击穿透未验证（仅 debug 二进制）。
5. **多 DPI / 多显示器**：仅在主屏 100% + 副屏 150% 的混合环境下测了主屏位置；150% 主屏、跨屏移动、不同 GPU/驱动下的透明黑底需人工复测（Task 5 会系统处理 DPI 几何）。
6. **任务栏不显示**：`skip_taskbar` 由 `ITaskbarList::DeleteTab` 实现，未截任务栏核实。
7. **全屏应用之上置顶**：P0 未验证（真全屏独占游戏等）。
8. **首次绘制白闪**：透明背景在首帧前是否闪白/黑需要人眼观察（代码已在首帧前设置 `html[data-window=panel]` 透明背景，但无法用静态截图证明）。
9. **拖拽/右键菜单期间强制交互**：Task 4/10 范围，未实现。
10. **生产日志**：本沙箱内无法验证文件日志写入 `%LOCALAPPDATA%\app.hangline.Hangline\logs`（正常环境预期可用）。

## 7. 结论

E1/E2 的自动化可验证部分全部通过：透明无底、卡片可点、其余区域点击穿透、进出卡片状态切换（25–41 ms、仅变化时调用）、隐藏无残留、不抢焦点。剩余为主观观感与正常桌面/生产构建的人工复核项，已列于第 5 节。P0 结论建议为 **PASS（待人工复核第 5 节）**。
