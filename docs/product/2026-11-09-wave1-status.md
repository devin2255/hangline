## 1. 范围与非目标

**做（Wave 1 全部）**：卡片操作面——右键菜单、hover 动作胶囊、标注工具补齐、标注分层回退、截图完成动作、空窗补按、托盘设置可解释化、第三热键。目标是把「截完图能做什么」从一个长按动作扩成一套**可发现、可预期、可回退**的操作面。

**不做（本 Wave 一行不碰）**：

- **任何新增窗口**：贴图 Pin、命令面板、录制 HUD 全部不做。原因：内存口径已修订为双口径（主进程 ≤150 MB 必须 / 进程树私有 ≤350 MB 暂定，见 spec §1.3 Amendment 2026-11-09），新增可视面按 **+70–135 MB/窗口** 估算；并见 [借鉴评估](2026-11-09-snowair-benchmark-iteration-plan.md) §9 争议 2 的结论。
- **任何联网能力**：OCR、翻译、上传、插件下载。保持「唯一网络请求 = 更新检查」。
- **多选/框选**：与 OLE 拖出手势冲突，属 Wave 2（`Ctrl` 点选）且不做框选。
- **搜索/标签/历史面板**（Wave 2+）、**标注工具超过 8 件**（马赛克/序号/高亮已定为本轮上限）。
- **面板窗口尺寸/定位改动**：右键菜单与胶囊都在既有 `panel` 窗口内渲染。面板高 189/210/246 dp（small/medium/large，medium 为默认 210 dp），**不扩窗口**是硬约束。
- **版本号 bump / CHANGELOG 转正**：Wave 1 验收前不做，避免「v1.2 名不副实」。

## 4. 风险与待裁决项

| # | 风险 | 具体机制 | 缓解 / 裁决需求 |
|---|---|---|---|
| **R1** | **210 dp 面板高度限制菜单尺寸，且菜单必须"抢回"点击** | 面板窗口只有 189/210/246 dp 高（medium 210 dp），菜单只能在窗口内渲染；实现按紧凑行高 26 dp × ≤6 行 + 3 条分隔线 ≈180 dp，顶部 clamp 到面板内（通常 y≈8）。更关键：面板的点击穿透由 Rust 33 ms 轮询 `set_ignore_cursor_events` 决定，**命中矩形只来自前端上报的卡片矩形**；菜单/胶囊打开后必须把它们的矩形并入 `set_hit_rects`，否则菜单区域会被判为穿透 → 点了没反应或点到桌面 | 实现内完成：菜单/胶囊矩形上报 + `setPanelBusy(true)` 防收起；真机回归必须覆盖「菜单区域可点、菜单外点击直达桌面」。大字号/150% 屏下 26 dp 行高与热区需实测，必要时菜单分两列或收起分组 |
| **R2** | **五路手势仲裁**：单击（延迟复制）/ 双击（打开）/ 长按（标注/裁剪）/ 按住拖出（OLE 模态）/ 右键（菜单） | 任意一路抢错键都会让用户丢图或误开编辑器；右键必须不启动单击复制与长按；胶囊在卡片**外**，`pointerleave` 时序要与既有 hover/press 动画兼容；**现有手势仲裁没有任何自动化测试**（P1 遗留） | 补纯函数级仲裁测试（`cardMenu` / `cardGesture`：右键不复制、菜单打开时抑制 click/dblclick/longpress/drag）；真机回归按「五路交叉」组合验证。这是本批次最高风险项 |
| **R3** | **Esc 关闭菜单与「绝不抢焦点」红线冲突**（待裁决） | 面板窗口是 `focusable:false`（不抢焦点是产品红线），点击它不会激活，**键盘事件可能根本到不了面板页面**——那么 W1.1 验收里的「键盘 Esc 关闭」就无法实现 | **需 lead 裁决**：方案 A（推荐）——菜单关闭依赖「点击外部 / 再右键 / 点 ×」，把 Esc 关闭降级为「若收到则支持」；方案 B——菜单打开时临时激活面板接收键盘，直接触碰「绝不抢焦点」红线，不建议。**先真机实测键盘可达性，再定案**，不要先按验收字面写死 |
| **R4** | **马赛克/模糊在 WebView2 canvas 的兼容性与一致性** | `mosaic` 需从底图取像素做缩小-放大（`drawImage`），`blur` 依赖 `ctx.filter`；两者都要求**预览与导出合成走同一条渲染路径**，否则「保存后和看到的不一样」；12000² 上限大图的离屏 canvas 内存/耗时需实测；`ctx.filter` 若在打包版不可用需降级为马赛克 | 实现内定降级路径（blur 不可用 → 马赛克）；导出与预览共用同一 `renderShapes(..., base)`；真机回归用一张大图 + 一张 150% 屏截图验证像素级一致 |
| **R5** | 内存/体积预算 | 本批次不新增窗口、不新增依赖；菜单/胶囊为面板内 DOM/CSS，进程树私有内存基线（293.8 MB）预计基本不变（±数 MB），**不触发** spec Amendment 的「+70–135 MB/窗口」评审线 | 批次合入后复测一次进程树内存即可；若异常增长 >20 MB 需回查（大概率是菜单复用大图预览导致，不应发生） |

## 6. 状态维护规则

- 本文件的「状态」列由 lead 在实现合入/验收后更新，取值只有四种：**待批次 2 → 实现中 → 已合入待真机 → 已验收**。
