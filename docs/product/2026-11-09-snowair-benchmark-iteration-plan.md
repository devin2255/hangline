> **类型**：产品决策文档（Product Owner 视角）
> **日期**：2026-11-09
> **对象**：Hangline v1.1.0（commit `93d6689`）
> **输入**：四份审计（`SnowAir` 工程机制 / `SnowAir` 产品 UX / Hangline 现状底账 / 竞品与市场），原始笔记见 `.research/notes/`（只读参考，已被 `.gitignore` 与 eslint 忽略）

## 0. 一页结论

### 0.1 三条战略判断

1. **「晾衣绳」形态已不是空白位。** Tendedero 发布（2026-10-07）后一个月内，GitHub 上「screenshot clothesline」相关仓库按搜索口径已达 33 个（含早期/空仓库），其中 Snapline 84★、Pegline、同名 Hangline 等已实现拖拽/标注/便签/多屏 DPI；**SnowAir 官方还内置了一个 Beta 插件「SnowAir 晾衣架」，产品承诺与 Hangline 几乎逐句相同**（"将截图自动挂在屏幕顶端，点一下复制、拖出分享，鼠标移开自动收起"）。
   → 形态是获客钩子，不是护城河。**防御窗口估计 6–12 个月**，赢法只能是"深度"，不是"广度"。

2. **Hangline 的成本结构和 SnowAir 完全不同。** SnowAir 是 Win32 自绘，多开一个窗口几乎免费；Hangline **每一个可视面 = 一个 WebView2**（当前 6 个），每个都要付内存（粗估 30–100 MB/个）、焦点、跨 DPI 重载、冷启动（编辑器实测 772 ms）、Z 序治理五份税。
   → SnowAir 里"开个新窗口就有"的能力（贴图、历史面板、命令面板、录制 HUD），在 Hangline 的边际成本曲线上全部变贵。**能在现有窗口内做完的，才是好迭代。**

3. **唯一可持续的差异化是「截图记忆」。** 免费克隆能抄走"挂一根绳子"，抄不走"截过的图能找回来"，也抄不走"四源接管 + 去重 + 保留/回收站语义"。
   → 下一步的价值不来自"再补一个截图工具功能"，而来自**把线从"最近 N 张"升级为"可检索的截图记忆"**。

### 0.2 如果只能做三件事

| 序 | 做什么 | 为什么是它 | 量级 |
|---|---|---|---|
| 1 | **把 1.1.0 的交付债还完**（56 处 MANUAL-PENDING、代码签名、内存基线、清理 4 个死 event 与 P0 脚手架残留） | 差异化点（拖拽/留存语义）恰恰最依赖真机验收；未验收=未交付，等于把 beta 当正式版发 | 1–2 周 |
| 2 | **卡片右键菜单**（分组 + 勾选 + 子菜单） | 设计文档 §3.1 承诺过、README 承认 V1.1 没做；SnowAir 的贴图菜单给了可直接照抄的契约与状态规则 | M |
| 3 | **标注补齐马赛克/序号/高亮** | 隐私涂抹是"敢把截图发出去"的前提；序号是步骤说明的高频刚需；都在现有编辑器窗口内，不加窗口不加网络 | M |

### 0.3 明确不抄（先看这里，避免跑偏）

| 不抄 | 一句话理由 |
|---|---|
| OCR / 翻译 / AI 文档识别（**作为功能卖点**） | 系统免费（Win11 截图工具 Text actions、PowerToys）、竞品免费（ShareX/PixPin/SnowAir Lite）；做它不加分，还要付隐私与精度客服成本。**但 OCR 可作为后台索引基础设施**，见 §9 争议 1 |
| 长截图 / 滚动拼接 | 红海且正确率长尾（对齐/粘性头/懒加载）；Snipaste 十年不做仍活。用互操作替代：让 PixPin/QQ 录长图存进监听目录，自动上线 |
| 自研录屏 / GIF | Hangline 已选 Game Bar 监听 + WinRT 裁剪路线，自研是第二套图形栈（WGC+D3D11+MF），成本 L–XL 且重复建设 |
| 图片编辑器（拼图/合并文档/PPTX） | 与"绳"形态无关，会稀释定位；最多在 v2 观察"多选卡片→合并 PDF" |
| 插件系统 / 插件市场 | 截图工具的插件=数据外泄入口；Tauri capability 是构建期静态的，没有 per-plugin 授权；先做 CLI 互操作 |
| 真实桌面毛玻璃 / 亚克力 | 透明 WebView2 无法 backdrop-blur 桌面（项目自己已写进代码注释）；换真模糊=换一套材质与 Win 版本矩阵，会推翻现有视觉证据基线 |
| 每屏一条线 / 多面板 / 常驻富工具条 | 直接改写"单面板 + 不抢焦点 + 低噪音"的产品灵魂 |

## 1. 调研口径与许可证边界（先划红线）

| 项 | 事实 | 对 Hangline 的含义 |
|---|---|---|
| SnowAir 许可 | **Apache-2.0**（本体），第三方组件另有 MIT/AGPL 等，`NOTICE` 有完整署名 | 法律上允许引用/修改/再分发，需保留版权与 NOTICE、标注修改；与 Hangline 的 MIT 兼容 |
| 能否构建 | **不能**：依赖定制版 Ling 框架（含未公开实现），不随仓库发布；只能用 Releases 的 exe | 我们无法"拿它当脚手架"；其源码只作阅读材料 |
| 发行形态 | 免费 Lite（单 exe 约 **4.42 MB**，无运行时依赖）+ 专业版（Qt6 闭源：AI、屏幕镜像、超级动作、快捷翻译） | 说明"轻量免费引流 + 增值付费"这条国内路径可行；但 Hangline 走不了 4 MB 这条线（见 §5.3） |
| 技术栈 | C++20 / Win32 / Direct2D / 自绘 UI / 进程内 DLL 插件 | 与 Tauri + React + Rust 无可直接复用的源码，**能搬的只有设计与机制** |
| 品牌资产 | 名称、图标、4 套主题（银灰/奶白/木棉/深沉）、文案 | **不得复制**。Hangline 已有原创视觉语言，混用会破坏品牌一致性并引发混淆 |

**执行口径**：抄契约，不抄代码；抄机制，不抄资产。若未来确实移植其代码片段，写入 `THIRD_PARTY_NOTICES.md` 并注明 Apache-2.0 与修改声明。

## 2. 两个产品不是一个物种

| 维度 | SnowAir 轻雪 | Hangline 晾图绳 |
|---|---|---|
| 产品本质 | **截图加工厂**：截图 → 标注/OCR/翻译/贴图 → 导出 | **截图收藏架**：截图 → 自动上线 → 复制/拖出/回看 |
| 核心时刻 | 截完图之后那 10 秒（加工质量） | 截完图之后的那一天（留存与找回） |
| 护城河 | 功能广度 + 免费 4 MB + 专业版变现 | 形态 + 空间留存 + Windows 平台细节 + 数据安全语义 |
| 扩展方式 | 原生 DLL 插件 + 按需下载组件（OCR/翻译语言包） | 单体应用 + 内置模块（当前） |
| 窗口模型 | 原生窗口接近零成本 | 每窗口一个 WebView2，**成本是架构级的** |
| 失败模式 | 功能杂、入口难找、专业版功能与免费版割裂 | 功能少、被免费克隆追平、体积/签名信任问题 |
| 可借鉴项 | 交互契约、状态机、工程纪律、发行策略 | —（我们不是它的子集） |

> **判断**：借鉴必须"降维"——把 SnowAir 的机制压进"绳"的形态里；凡是需要**新窗口 / 新常驻 UI / 联网**的，先按 §6 的五道闸门打回。

## 3. 市场校准：为什么本轮优先级不是"追功能"

- 形态红利正在消失：Tendedero 首月 24,007 下载、3,092★（作者自述 + GitHub API，检索 2026-11-09），证明需求真实；但同期 33 个相关仓库、Snapline 84★、Pegline、同名 Hangline 等说明**供给也在快速跟上**。
- SnowAir 晾衣架插件是"免费 + 全家桶导流"的镜像竞品，且用户反馈"装了不知道在哪用"——**说明把入口/交互/留存语义做对很难，这正是 Hangline 的机会**（它就是产品本体，不是插件）。
- 需求侧证言：PixPin 历史功能帖用户说"历史区域使用概率挺高，尤其截图演示操作步骤、对比屏幕效果"；少数派/Tendedero 报道把痛点说得很直白——"浮动缩略图挡视线、截图堆桌面找半天"。
  → **留存不是大众刚需，而是一天截 10 张以上、跨应用搬运图文人群的强痛点。** 产品叙事应锁定这群人。

**结论**：6–12 个月窗口内，Hangline 要做的是"把承诺兑现 + 把深度做出来 + 把信任补齐"，而不是把 SnowAir 的功能清单抄一遍——那会把 12 个月变成 6 个月。

## 4. 现状底账（只列影响决策的）

### 4.1 真实具备（不建议重做）

4 条截图链路 + BLAKE3 跨源去重（20 条 LRU + 5s claim）；5 种卡片手势（单击复制三格式 / 双击 / 长按 / 拖出 OLE / × 回收站）；5 工具 Canvas 标注器（pen/rect/arrow/text/crop，24 步 undo，裁剪可二次编辑）；WinRT 录屏裁剪（保留音轨、原子替换）；数量/年龄双层保留（自有文件进回收站，其余只下线）；多屏 DPI（单面板跟随 + 500ms dwell）；全屏抑制；2 个全局热键（注册新键先于释放旧键、冲突回滚）；32 项托盘设置；签名更新（唯一网络行为）；中英双语（54 key，Rust 托盘文案编译期穷举）。

> 这些是**免费克隆 6 个月内抄不全**的部分，是本轮迭代必须保护的资产。

### 4.2 真实缺口（决策相关）

卡片右键菜单（spec 承诺、未实现，且 WebView2 默认菜单未屏蔽）；hover 动作条；多选/批量；卡片备注/标签/搜索；贴图 Pin；OCR；命令面板；马赛克/序号/高亮；形状二次选中；截图完成动作可配置；完整设置窗口；真 portable；HEIC；`CF_BITMAP` 采集。

### 4.3 交付债（比功能缺口更该先还）

| 债 | 证据 | 影响 |
|---|---|---|
| **56 处 MANUAL-PENDING**（P1=22、P2=13、P3=7、P4=10、P5=4） | `docs/acceptance/P*-core.md` | 没有任何里程碑被标为"验收完成"；差异化点（拖拽/回收站/多屏）恰好全在人工待验里 |
| 安装器未签名 | `README.md:226-228` | SmartScreen 是当前最大转化漏斗；在市场被 90 KB–4 MB 免费替代包围时，签名比新功能更能提升下载转化 |
| **内存目标从未实测** | spec 目标 ≤150 MB，docs 无 RSS 数值 | 直接决定"能不能加窗口/加 Pin"，是所有"新可视面"决策的前置数据 |
| `pnpm check` 曾为红（本次调研 clone 触发，已修） | 本次已把 `.research/` 加入 eslint ignore 与 `.gitignore`，`eslint` 复跑 exit 0 | 质量门必须永远一键通过 |
| 4 个 IPC event 发射后无消费者（`clipboard-copied` / `second-instance` / `fullscreen-state` / `hotkey-error`） | 审计 §2.2 | IPC 表面冗余，后续容易被误判为"已有此能力" |
| `drag_demo_file` P0 脚手架仍在 release handler | `lib.rs:826`、`dragout.rs:392-402` | 发布物带调试命令 |
| 单文件过大：`Panel.tsx` 1995 行、`capture.rs` 2346、`reveal.rs` 2341、`dragout.rs` 1732 | 审计 §3.5 | 新增能力的第一道阻力是改这些文件，不是写新文件 |
| 手势仲裁零测试覆盖 | `P1-core.md:373` | 任何新入口（右键/hover/多选）都是最高风险区 |

### 4.4 工程纪律上的对照（SnowAir 已经做过而我们没有）

SnowAir 有一套 `--selftest`（无窗口、退出码=失败数、日志落盘），因为它是**没有 CI** 的项目；Hangline 有 CI，所以借鉴定位不同：**把 selftest 做成"用户现场诊断开关"，而不是回归门禁**。同理它的 `config.json` 三层兜底（原子写 / `.bak` 恢复 / 读失败进只读会话）是 Hangline 缺的约 100 行防御，成本极低。

## 5. 借鉴映射矩阵（本报告核心）

> 判定：✅ 采用 / ⚠️ 改造后采用 / ⏸ 后置观察 / ❌ 不采用。成本量级：S=1–2 天、M=3–5 天、L=1–2 周、XL>2 周（工程估算，非工期承诺）。

### 5.1 交互契约类（SnowAir 已被用户验证过的"怎么做"）

### 5.3 关于"体积"这条，必须说清楚

审计确认：SnowAir 的 **4.42 MB 是解压后可直接运行的全部内容**（单 exe、无运行时依赖）；Hangline 的 **7.32 MB 是压缩后的 NSIS 安装包**，其中 1.90 MB 是 WebView2 引导器，应用 exe 本体远大于 4.42 MB。
→ **4 MB 这个数字不可搬**：要搬等于换技术栈（自绘原生 UI）。可搬的是**纪律**：体积门禁 + 按需组件 + 增量体积审批。
→ 对市场的正确回应不是"我们也很小"，而是"我们小得有内容"：把玻璃材质/动画/多屏/录制裁剪/零网络当卖点，并用代码签名 + Store/winget 抵消"来路不明"的信任损失。

## 6. 五道闸门（可复用的产品决策工具）

以后每个候选迭代项，先过这五问；任何一问过不了，就要么改造方案、要么放弃。

| 闸 | 问题 | 为什么是第一原则 |
|---|---|---|
| 1 | **要不要新开窗口？** | 每个 WebView2 付内存/焦点/DPI/冷启动/Z 序五份税；SnowAir 免费拿到的能力，在 Hangline 都是架构级成本 |
| 2 | **要不要联网？** | "唯一网络请求是更新检查"是本产品最独特的定位；任何模型/组件下载都会改写它，属产品决策而非工程决策 |
| 3 | **会不会让线变吵？** | 玻璃/绳线/微风/不抢焦点/低噪音是一体的；任何常驻可见 UI 都要先回答"它凭什么占用屏幕顶部" |
| 4 | **会不会改变既有手势？** | 单击复制/双击打开/长按编辑已把鼠标用满，且手势仲裁无测试覆盖；新入口优先用悬停时机、修饰键、热键 |
| 5 | **有没有真机证据？** | 本项目自己的标准是 MANUAL-PENDING 不算通过；新能力验收必须含真机物理输入 |

**产品灵魂红线（来自代码审计，可核验）**：R1 玻璃是渐变仿制的（透明 WebView2 不能 blur 桌面）· R2 绳/夹子几何常量 · R3 所有运动走同一弹簧积分器 · R4 60fps 是 DoD · R5 面板/飞入层永不抢焦点 · R6 33ms 轮询点击穿透 · R7 单面板不驻多屏 · R8 无 Toast/无右键菜单/无常驻工具条的低噪音 · R9 唯一网络=更新 · R10 安装包/内存/CPU 预算。

> 这 10 条不是形容词，是写进代码与验收文档的可审计约束。任何新能力的"改造配方"都必须挂在它们上面。

## 9. 四个需要当场裁决的争议

### 争议 1：OCR 到底做不做？（市场说"不"，UX 审计说"值得"）

**裁决：做索引，不做功能。**
- 不做：识别按钮、原文重绘、翻译、文档/表格/公式识别、内置模型、联网下载模型。
- 要做：`Windows.Media.Ocr`（系统组件，**0 字节增量、离线、不上传**）在后台给卡片建可搜索文本；用户感知是"搜截图里的字"，不是一个叫 OCR 的功能。
- 前置条件（PoC 判据）：① 目标机 `AvailableRecognizerLanguages` 探测与降级；② 中文清晰 UI 文字命中率达标（先定门槛，例如关键词召回 ≥80%）；③ 峰值内存与索引体积可接受；④ 索引入口默认开启还是可选，需明确隐私文案。
- 这条同时满足市场报告（不把 OCR 当卖点）与 UX 审计（卡片级提取值得做），并守住 R9（不联网）。

### 争议 2：贴图 Pin 做不做？（UX 审计排第 3，工程审计说成本 M–L）

**裁决：v2 之前不做。**
- 理由：每个 Pin 是一个 WebView2（**2026-11-09 真机实测：Hangline 进程树私有内存已达 293.8 MB、RSS 571 MB，单个 WebView2 子进程 20–135 MB**）；3 个 Pin 会把本已超标的进程树继续推高；跨 DPI 拖动要重建窗口；Z 序要跨 3 个 Rust 模块协调。而 Pin 是 Snipaste/PixPin/SnowAir 的红海，做了不加分。
- 替代：把"贴到桌面"的诉求用**拖出成文件**（已有）承接；若未来做，先做**单个 Pin + `focusable:false` + 显式 Z 序**，并先补内存基线。

### 争议 3：历史面板 vs 搜索层？（市场建议 Pro 押"搜索/标签"）

**裁决：做搜索层，不做历史面板。**
- 独立历史面板会让产品变成"又一个截图管理器"，稀释"一条安静的线"；而搜索浮层是"就地调用、用完即走"，符合 R8。
- 数据模型（备注/标签）先落，界面后做；搜索浮层是新开一个**可聚焦小窗**——这是唯一可接受的新窗口类型（编辑器/输入类），且必须像 annotate/trim 一样在关闭时把 busy 状态还给面板。

### 争议 4：什么时候商业化？

**裁决：1.x 保持 MIT 免费，不设 Pro 边界；把 Pro 的候选价值先做出来再谈。**
- 免费层必须保留全部核心体验（否则用户直接去用免费克隆）。
- Pro 候选（按市场锚点 ¥68 买断 / $24.99，含 1 年更新）：搜索/标签/备注、批量导出、按应用/窗口的自动留存规则、多屏布局、录屏裁剪增强、**商用授权**。
- 不建议订阅、不建议自建云：与"本地、无账号、唯一网络=更新"的定位冲突。
- 商业化前必须完成：代码签名 + Store/winget 分发 + 一条 15–20 秒演示视频（Tendedero 的增长主要靠它）。
